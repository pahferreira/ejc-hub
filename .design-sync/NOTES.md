# design-sync notes — ejc-hub

Repo-specific gotchas for future syncs. The design system lives in `app/` (a
Vite React app, not a published library), so several things are non-default.

## Shape and entry

- **This is an app, not a package.** `app/package.json` is `private`, has no
  `main`/`module`/`exports`, and ships no `dist/`. The converter's storybook
  shape still needs a real built entry plus a `.d.ts` tree, so
  `.design-sync/build-ds.sh` synthesizes both. It is wired as `cfg.buildCmd`;
  run it before the converter on every re-sync.
  - `app/.ds-entry.mjs` — bundle entry: `export *` of every non-story `.tsx`
    under `src/components` (absolute paths).
  - `app/.ds-entry/index.ts` + `app/tsconfig.ds.json` → `app/dist-ds/` — the
    declaration tree. `app/index.d.ts` re-exports its entry, which is what
    `projectFor()` looks for (no `types` field in package.json).
  - All four are gitignored and regenerated by the script. **Do not add the
    barrel under `app/src/`** — `tsconfig.app.json` includes `src`, so it
    would land in the repo's own `tsc -b` output and add errors.
- `app/node_modules/app` is a self-symlink to `app/`. Harmless, and it lets
  bare `app` imports resolve. Recreate on a fresh clone if anything needs it:
  `ln -sfn .. app/node_modules/app`.
- Run the converter from the repo root with
  `--node-modules app/node_modules --entry app/.ds-entry.mjs`.

## Toolchain

- **rollup 4.45.0 (the locked version) cannot build this Storybook.** It dies
  with `Cannot add property 0, object is not extensible` — a rollup bug, not a
  repo problem. The app's own `vite build` is unaffected, which is why this
  only shows up here. Worked around without touching the lockfile:
  `cd app && npm install --no-save --no-package-lock rollup@4.52.5`.
  **This is not persistent** — a plain `npm ci` restores 4.45.0 and the
  reference build breaks again. Re-apply it on a fresh clone, or bump rollup
  in `package.json` for real.
- Node 24.13.0 and Node 20.20.0 both hit the rollup bug, so it is not a Node
  version issue.

## Source fixes made during the first sync

- `app/src/components/Sidebar/sidebar.ts` → **renamed to `sidebarNav.ts`**
  (4 importers updated). It differed from `Sidebar.tsx` only by case, and on
  macOS's case-insensitive filesystem that broke two things: esbuild resolved
  `./sidebar` to `Sidebar.tsx` itself, and `tsc` refused to emit declarations
  because both files mapped to `Sidebar.d.ts`. The rename is the real fix —
  adding explicit extensions was not enough.

## Pre-existing issues (NOT caused by the sync)

- `app/src/hooks/useAuthentication.ts:23,24` — two `strict` errors
  (`string | undefined` not assignable to `string`). `npx tsc -b` reports them
  on a clean checkout too. The declaration build tolerates them
  (`|| true` in build-ds.sh) since emit still succeeds.
- `Option` is exported by both `Selector` and `MultiSelector`, so `export *`
  drops it as ambiguous (TS2308). Neither is a component, so nothing is lost.

## Converter configuration

- **`cfg.provider` = `MemoryRouter`.** Stories get a router from
  `storybook-addon-remix-react-router`; previews do not, so the provider
  supplies one. `MemoryRouter` reaches the bundle via
  `.design-sync/ds-providers.ts` listed in `cfg.extraEntries`.
- **`.design-sync/overrides/story-imports.mjs` (lib fork).** Two packages the
  upstream `@storybook/*` stub filter misses:
  - `storybook-addon-remix-react-router` — `withRouter` is a decorator, so the
    fork stubs it as a **passthrough** (`storyFn => storyFn()`), not an inert
    callable; an inert one returns a proxy where React expects an element.
    `reactRouterParameters` and friends return `{}`.
  - `vitest` — `TeamAvatar.stories.tsx` calls `describe`/`it` at module scope.
  The fork also makes the stub filter config-driven via
  `cfg.storyImports.inert`. Note esbuild's `__toESM` copies own enumerable
  props, so the generic inert Proxy never satisfies a **named** import — any
  future package in this situation needs a real stub body in `REPO_STUBS`.
- `cfg.overrides.WeekAvailability.skip` drops the `Empty` story: the component
  deliberately returns `null` for an empty week, and the render check reads
  the first cell's root, so an empty first cell fails the whole card.
- `cardMode` overrides: `Sidebar`, `FilterCheck`, `FilterToggle`,
  `TeamDetailContent` are `column` (wider than a grid cell);
  `FeeBulkSelectionBar` and `FeeConfirmationModal` are `single` (both are
  `position: fixed`/portal overlays).
- `titleMap` excludes `Configure your project` (Storybook's onboarding doc).
- CSS comes from `[CSS_FROM_STORYBOOK]` — Tailwind v4 has no static
  stylesheet to point `cssEntry` at, so the converter scrapes the compiled CSS
  out of the reference storybook build. This is correct and expected; it means
  **the reference storybook must be rebuilt whenever styles change**.
- `[FONT_REMOTE]`: Inter, Nunito Sans, Playfair Display load from a remote
  font host `@import`. Not shipped in `fonts/`; they resolve at runtime.

## Grading conventions established on the first sync

- **[GENERAL] `play()` artifacts are an accepted `close`.** Several stories run
  Storybook `play()` functions that type into fields or click controls
  (`SearchInput`, `Checkbox/Checked`, `RadioGroup/WithSelection`, `Navbar`).
  The reference panel therefore shows typed text or a blue browser focus ring
  that the preview never will — previews deliberately do not run play
  functions. Component styling is identical in every such case. Graded `close`
  with a note rather than chased; there is no knob that would fix it, and
  "fixing" it would mean neutralizing the story.
- **[GENERAL] `[ASSETS_BLOCKED]` is a false positive here.** The only host it
  reports is `example.invalid`, which `UserAvatar`'s *Broken Photo* stories use
  on purpose to exercise the initials fallback. Real remote images
  (`i.pravatar.cc`) load on both panels, confirming the capture shell has
  egress. Do not treat this warning as a sandbox problem.
- Sheet panels are often rendered at different scales, which can make borders
  and type look different. Check `_screenshots/compare/raw/*.png` before
  grading a size/color delta — `Input/RequiredInput` looked off in the sheet
  and was pixel-identical in the raw captures.
- `Navbar`'s stories point `imageSrc` at `/church.svg`. It is broken on BOTH
  panels (it is a story fixture served from `app/public`, not part of the
  bundle), so it grades `match`. The component takes the image as a prop, so
  designs supply their own.
- `[STORY_CAP]`: `InscriptionCard` has 8 stories and compare captures 6 by
  default. The two uncaptured stories were never individually graded — raise
  `--max-stories` if they need covering on a later sync.

## Component-specific findings

- **`TeamAvatar` stories are broken in the repo's own Storybook.**
  `TeamAvatar.stories.tsx` imports `describe`/`it`/`expect` from `vitest` and
  runs them at module scope, which cannot work in a built Storybook — all three
  stories fail with `Cannot read properties of undefined (reading
  'customEqualityTesters')`. The design-sync preview renders correctly (the
  fork stubs vitest), so the component itself is fine and was graded from its
  own render. **Worth fixing in the repo**: move those assertions into a real
  `getInitials.spec.ts` next to the existing spec files.
- **`FeeConfirmationModal`** reports `sb-error` on all 4 stories ("no storybook
  root content") because it renders through a portal outside storybook's canvas
  root. `cardMode: "single"` captures it correctly in the preview; graded from
  that render.
- **`TeamBox` can never pixel-match.** `TeamBox.tsx` picks its status-dot colour
  with `Math.random()` from `BROWN_COLORS`, with no prop override — the colour
  differs on every render. It is the only component in the repo doing this.
  Accepted as `close`; do not chase it.
- **`Drawer`** legitimately renders the same closed-state trigger in all three
  stories, which is why validate reports `[RENDER_THIN] variants render
  identically`. Not a defect — leave it.

## Owned previews (`.design-sync/previews/`)

Both are committed and win over the generated twins. Neither changes story args.

- **`FeeBulkSelectionBar.tsx`** — the bar is `fixed inset-x-0` with **no
  vertical anchor**, so it resolves to its static position; stories that render
  only the bar landed at the cell's top edge and were clipped
  (`[RENDER_BLANK]`). A spacer wrapper gives it room. Its `Hidden` export is
  removed because the story is skipped in config (it renders nothing by design).
- **`Sidebar.tsx`** — the two `NestedRoute*` stories declare their location via
  `reactRouterParameters`, which the story-imports fork stubs out, so the
  `bg-tertiary` active highlight was lost. `AtRoute` **navigates** the
  provider's MemoryRouter via `useNavigate`. It must NOT nest a second
  `MemoryRouter`: React Router v7 throws *"You cannot render a `<Router>`
  inside another `<Router>`"*. `useNavigate` is exported through
  `.design-sync/ds-providers.ts` for this.

## Re-sync risks — what to watch next time

- **The rollup pin is the most likely thing to break a re-sync.** It is not in
  `package.json`; a fresh `npm ci` silently reverts to 4.45.0 and the reference
  storybook build fails (exit code 0, no `iframe.html`). Always check
  `.design-sync/sb-reference/iframe.html` exists and is >10KB.
- **CSS is scraped from the reference storybook** (`[CSS_FROM_STORYBOOK]`),
  so `sb-reference` and the bundle must be rebuilt **together**. If styles
  change and only the bundle is rebuilt, every grade compares against stale CSS.
  `.design-sync/build-ds.sh` does both — use it.
- **The two owned previews are tied to upstream APIs.** `Sidebar.tsx` imports
  `ROUTE_PATHS.EVENT_FEE_MEMBERS` and hardcodes `/teams/liturgia`; if the
  stories' routes change, the highlight silently goes back to being wrong.
  `FeeBulkSelectionBar.tsx` assumes the bar stays `fixed` with no anchor — if
  the component gains a `bottom` anchor the spacer becomes unnecessary.
- **Story caps.** These components have more stories than the 6 captured by
  default, so their tail stories were never individually graded:
  `CoordinatorCandidateRow` (12), `EventBanner` (9), `CoordinatorSlots` (8),
  `InscriptionCard` (8), `TeamMembersFeeCard` (8), `TeamBuildingCard` (7),
  `TeamCard` (7), `EventFeeMembersTable` (7), `TeamHealthCard` (7). Raise
  `--max-stories` if the tail carries distinct variants.
- **Accepted `close` grades** (all play()-driven, none fixable without mutating
  a story): `SearchInput/Default`, `Checkbox/Checked`,
  `RadioGroup/WithSelection`, `Pagination/Default` + `LastPage`,
  `Table/WithMultipleActions` + `Sortable`,
  `FeeByTeamCard/SortedByPendingDescending`, `TeamBox/*` (random dot).
- **Toolchain assumed**: Node 24.13.0, npm 11.6.2, storybook 9.1.20,
  vite 7.0.4, React 19.3.0, Tailwind v4. Fonts (Inter, Playfair Display) load
  from Google Fonts at runtime — they are never bundled.
